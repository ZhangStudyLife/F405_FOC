# MT6835 驱动

MagnTek / 纳芯微 MT6835 —— 21-bit 绝对角度磁编码器，SPI 接口。

本工程用法：SPI3（10.5 MHz，模式 3）+ PA0 片选，供 20 kHz FOC 读取转子绝对角度。

---

## 1. 文件职责

| 文件 | 职责 | 是否含 HAL |
|---|---|---|
| `mt6835.h` | 公开 API、寄存器映射、错误码、`mt6835_port_t` 接口定义 | ❌ |
| `mt6835.c` | 协议实现：帧收发、解包、CRC-8、多圈展开 | ❌ |
| `mt6835_port_stm32.h/.c` | 板级适配：把 bsp_spi / bsp_gpio / bsp_time 接到驱动上 | ✅ |

`mt6835.c` 不含任何 ST 头文件，所以**可以在 PC 上直接编译做单测**：

```bash
gcc -std=c11 -Wall -Wextra -O2 -I App/Hardware/mt6835 \
    test.c App/Hardware/mt6835/mt6835.c -o test
```

## 2. SPI 协议

> 以下每条都已对照**官方数据手册 MT6835 Rev 1.3（2022 年 12 月）**核对：
> 7.6.2 SPI 时序 / 7.6.3 SPI 协议 / 7.6.4~7.6.9 各命令 / 第 10 章寄存器表。

### 引脚（数据手册 7.1 节 I/O 引脚配置表）

| 芯片引脚 | 名称 | 方向 |
|---|---|---|
| 5 | **MISO** | 数字**输出**（MT6835 → 上位机） |
| 6 | **MOSI** | 数字**输入**（上位机 → MT6835） |
| 7 | **SCK** | 数字输入 |
| 8 | **CSN** | 数字输入，SPI 使能控制脚 |

**接线是"同名接同名"**，不要像 UART 那样交叉：MCU 的 MOSI 接芯片的 MOSI，
MCU 的 MISO 接芯片的 MISO。芯片引脚名是按主机视角命名的
（"MOSI = 上位机输出、MT6835 输入"），所以名字相同就是对接。

SPI 用的是**专用引脚**（数据手册 7 节开头："21 位的绝对角度数据可以通过 4 线 SPI 的
专用引脚读取"），不需要任何模式选择脚配合，上电即可用。

### 通信参数

* **模式 3**：CPOL=1（空闲高），CPHA=1（第二沿采样）
  —— 数据手册原文："MT6835 的 SPI 使用模式 3（CPOL=1, CPHA=1）传输数据……
  MT6835 在时钟上升沿采样数据"
* MSB first，8 bit
* **SCK 上限 16 MHz**（TSCK ≥ 60 ns）；本工程 10.5 MHz（PCLK1 42 MHz ÷ 4）
* **非通信状态下 SCK 必须保持高电平**（模式 3 的空闲电平天然满足）
* 片选 CSN **低有效**，下降沿激活一次通信，上升沿结束
* **MISO 在非输出时始终为 Hi-Z 高阻** —— 所以空闲时量到悬空电平是正常的

**时序要点（数据手册 7.6.2 表）**

| 参数 | 含义 | 要求 | 本工程 |
|---|---|---|---|
| TL | CSN 下降沿 → 第一个 SCK 下降沿 | **≥ 100 ns** | HAL 调用开销已远超 |
| TSCK | 时钟周期 | ≥ 60 ns | 95 ns ✓ |
| TSCKL/TSCKH | 时钟低/高电平时间 | ≥ 30 ns | 47.5 ns ✓ |
| TH | 最后一个 SCK 上升沿 → CSN 上升沿 | ≥ 0.5·TSCK | 远超 ✓ |
| TST/THD | MOSI 建立/保持 | ≥ 10 ns | AF 推挽输出满足 ✓ |

### 2.1 突发读角度（快路径，48 bit = 6 字节）

一次片选拿全 **角度 + 状态 + CRC**，这是为 20 kHz 控制环准备的唯一 I/O 入口。

```
MOSI:  A0        03        00    00    00    00
       └─ 0xA0 = OP_BURST(0b1010) << 4
                 └─ 0x03 = 角度寄存器起始地址

MISO:  [0]  [1]   [2]       [3]         [4]                     [5]
       命令回显   angle[20:13] angle[12:5] angle[4:0]<<3|status[2:0]  CRC-8
                 └────────── 21 bit 角度 ──────────┘
```

解包（`mt6835_decode_angle`）：

```c
raw    = ((uint32_t)rx[2] << 13) | ((uint32_t)rx[3] << 5) | ((uint32_t)rx[4] >> 3);
status = rx[4] & 0x07;
```

### 2.2 寄存器访问（慢路径，24 bit = 3 字节）

```
命令字 = (op << 12) | (addr & 0x0FFF)      // 16 bit
发送:  [cmd_hi] [cmd_lo] [data_out]
接收:  [  回显  ][  回显  ][data_in]        // 数据在第 3 字节
```

| 操作码 | 值 | 说明 |
|---|---|---|
| `MT6835_OP_READ` | `0x3` | 读寄存器 |
| `MT6835_OP_ZERO` | `0x5` | 以当前位置为零点 |
| `MT6835_OP_WRITE` | `0x6` | 写寄存器 |
| `MT6835_OP_BURST` | `0xA` | 突发读角度 |
| `MT6835_OP_PROG` | `0xC` | 刷写 EEPROM |

**烧录 EEPROM（`0xC000`）** 和 **自动置零（`0x5000`）** 成功时第 3 字节返回 **`0x55`**。
**普通写寄存器（`0x6`）数据手册没有定义应答**，写没写进去要靠回读确认。

### 2.3 寄存器映射

| 地址 | 宏 | 说明 |
|---|---|---|
| `0x001` | `MT6835_REG_USERID` | **客户保留 EEPROM 寄存器，不是器件 ID**（出厂默认 `0x00`） |
| `0x002` | `MT6835_REG_RESERVED` | Not Used |
| `0x003` | `MT6835_REG_ANGLE1` | 角度高字节，突发读起始地址 |
| `0x004`–`0x006` | `ANGLE2`–`ANGLE4` | 角度中/低字节 + 状态 |
| `0x007`/`0x008` | `ABZ_RES1/2` | ABZ 分辨率、ABZ 使能、AB 交换 |
| `0x009`/`0x00A` | `ZERO1`/`ZERO2` | 零位（`0x00A` 与 `OPTS0` 共用地址，仅位域不同） |
| `0x00B`–`0x00E` | `OPTS1`–`OPTS4` | UVW、PWM、迟滞、方向、自校准频率 |
| `0x011` | `OPTS5` | 带宽 |
| `0x013` | `NLC_BASE` | 非线性校准表，192 字节 |
| `0x113` | `CAL_STATUS` | 自校准状态 |

### 2.4 CRC-8

* 多项式 **`x^8 + x^2 + x + 1` = `0x07`**
* 初值 `0x00`，**无最终异或**
* 覆盖 **24 bit**：`angle[20:13]`、`angle[12:5]`、`angle[4:0]<<3 | status[2:0]`
  —— 正好就是突发帧的 `rx[2] rx[3] rx[4]` 三字节

驱动里 `mt6835_crc8()` 按字节迭代实现。已用穷举（211 个角度 × 8 个状态）
与逐字节独立参考实现交叉验证一致，另有手算已知值校验：

| 输入 | 期望 CRC |
|---|---|
| `angle=0x000000, status=0` | `0x00` |
| `angle=0x1FFFFF, status=7` | `0x0F` |

## 3. 驱动行为约定

### 3.1 快速上手

```c
#include "bsp_time.h"
#include "mt6835.h"
#include "mt6835_port_stm32.h"

mt6835_t encoder;

bsp_time_init();                                   /* DWT，必须先调 */
if (!mt6835_port_stm32_bind(&encoder, &hspi3,
                            MT6835_CS_GPIO_Port,       /* GPIOA */
                            MT6835_CS_Pin)) {          /* GPIO_PIN_0 */
    /* 建链失败：见下面第 5 节排障表 */
}

/* 20 kHz 控制中断里（例如 ADC 注入转换完成回调） */
if (mt6835_read(&encoder) == MT6835_OK) {
    float mech = mt6835_angle_rad(&encoder);       /* [0, 2π) */
    float elec = mech * (float)POLE_PAIRS;         /* 电角度，FOC 用 */
}
```

### 3.2 出错时的取值语义（重要）

| 情况 | 返回 | `sample` 内容 |
|---|---|---|
| 正常 | `MT6835_OK` | 更新为新采样 |
| **CRC 失败** | `MT6835_ERR_CRC` | **保留上一次有效值**，`crc_errors++` |
| 传输超时 | `MT6835_ERR_TIMEOUT` | **保留上一次有效值**，`comm_errors++` |
| 未建链 | `MT6835_ERR_NOT_INIT` | 不变 |

设计取舍：**宁可复用旧角度，也绝不把被污染的角度送进控制环**——
一次错误的角度就是一次转矩尖峰。是否停机由上层用 `mt6835_healthy()` 决策：

```c
if (!mt6835_healthy(&encoder)) {
    /* 已建链失败 / CRC 出错 / 传感器报了 超速·弱磁·欠压 告警 */
    foc_disable();
}
```

`MT6835_ST_WEAK_FIELD`（磁场过弱）通常意味着磁钢脱落或气隙过大，此时角度完全不可信。

### 3.3 零点与方向

两种方式，**推荐软件零点**：

| 方式 | API | 说明 |
|---|---|---|
| **软件零点**（推荐） | `mt6835_set_zero_offset(dev, raw)` | 只影响驱动输出，不写芯片，标定值由上层保存 |
| 硬件零点 | `mt6835_set_zero_here(dev)` | 发 `0x5000` 命令改芯片零点，属破坏性操作 |

`mt6835_set_direction(dev, true)` 用于编码器计数方向与电机正转相反时。
两者都会重置多圈基准，避免角度跳变被误记成整圈。

### 3.4 多圈展开

`mt6835_total_counts()` / `mt6835_full_angle_rad()` / `mt6835_turns()` 提供
跨圈累计。展开判据是"相邻两次采样之间角度变化不超过半圈"：

```
delta = raw - prev_raw;
if (|delta| > 2^20)  delta ±= 2^21;
```

20 kHz 采样下这个假设允许 **10000 转/秒**，远超任何电机，绝对安全。
累计量用 `int64_t`，无溢出风险。

⚠️ 该累加假设"两次采样之间电机没有真正转过半圈以上"。若你在
`mt6835_read()` 之外还手动插入长时间间隔（比如断点调试），请先
`mt6835_set_zero_offset()` 重新定基。

## 4. 时序与实现注意事项

| 项 | 处理 |
|---|---|
| **上电就绪** | 上电后芯片需要时间初始化，此期间 SPI 不应答。`mt6835_init()` 先等 `MT6835_POWER_ON_DELAY_MS`（默认 20 ms），再最多重试 `MT6835_INIT_RETRY`（默认 5）次建链探针 |
| **建链探针** | **MT6835 没有器件 ID 寄存器**。0x001 是"客户保留"寄存器，新芯片读回 `0x00`。所以 `mt6835_probe()` 用"写 `0x5A` → 回读比对 → 恢复原值"来验证双向通信，**不能**拿 0x001 的值当判据 |
| **片选必须释放** | 所有返回路径（含失败）都保证 `cs_select(false)`。CSN 停在低电平会让芯片认为通信没结束，后续帧全部无效 |
| **帧间片选高电平** | 慢路径每帧后插 `MT6835_TCSH_MIN_US`（默认 1 µs）。快路径相邻帧相隔整个控制周期（50 µs），天然满足，不插延时 |
| **SPI 状态机自愈** | `bsp_spi_transfer()` 失败后会调 `HAL_SPI_Abort()`。否则一次超时会让 `hspi->State` 停在 BUSY，之后每次调用都立刻失败，表现成"偶发一次超时后编码器永久读不到" |
| **超时值** | `MT6835_SPI_TIMEOUT_MS = 1`。一帧 6 字节只需约 5 µs，1 ms 已是三个数量级余量。**不要用 `HAL_MAX_DELAY`**，芯片掉线时会把控制中断永久挂死 |
| **片选翻转速度** | `bsp_gpio_out_init()` 把 PA0 从 CubeMX 的 `SPEED_FREQ_LOW` 提到 `HIGH`，保证 10.5 MHz 下的时序余量 |
| **不做 `Error_Handler()`** | 初始化失败只返回错误码。控制工程里让 MCU 关中断死循环是不可接受的 |
| **慢路径禁止进中断** | `mt6835_read_reg` / `write_reg` / `store_eeprom` 是 3 字节帧 + 帧间延时，只能主循环调用。`store_eeprom` 之后还要等 ≥ 6 秒再断电 |
| **实例数** | `MT6835_PORT_MAX_INSTANCES`（默认 2）。每次 `bind` 占用一个静态槽位；建链失败会自动归还 |

## 5. 上板验证与排障

### 验证步骤

1. `foc.sh build Release && foc.sh flash Release`
2. `foc.sh debug --batch "print g_mt6835_err" "print g_mt6835_loops" "print g_mt6835_raw" "print g_mt6835_read_ns"`
3. 隔几秒再看一次 `g_mt6835_loops`，应明显增长（确认主循环在跑）
4. 手动转动电机轴，`g_mt6835_raw` 应在 `[0, 2097152)` 内平滑变化，转一圈回到起点
5. 连续跑 60 秒，`g_mt6835_err` 应恒为 0

### 观测变量

| 变量 | 含义 |
|---|---|
| `g_mt6835_raw` | 最近一次有效采样的原始 21 bit 角度 |
| `g_mt6835_err` | `0` = 正常；否则为 `mt6835_status_t + 1` |
| `g_mt6835_read_ns` | 同步阻塞读的耗时（纳秒），**评估 SPI 效率就看它** |
| `g_mt6835_read_cycles` | 同上，原始 CPU 周期 |
| `g_mt6835_async_start_ns` | 异步 `mt6835_read_start()` 的 CPU 开销 |
| `g_mt6835_async_finish_ns` | 异步 `mt6835_read_finish()` 的开销（bring-up 里中间插了 6 µs 模拟运算） |
| `g_mt6835_loops` | 轮询次数 |
| `g_mt6835_status` | 传感器告警位（bit0 超速 / bit1 弱磁 / bit2 欠压） |

`g_mt6835_err` 与 `mt6835_status_t` 的换算：

| `g_mt6835_err` | 枚举 | 含义 |
|---|---|---|
| 1 | — | `mt6835_port_stm32_bind()` 直接失败（参数/实例池） |
| 2 | `MT6835_ERR_PARAM` | 入参非法 |
| 3 | `MT6835_ERR_NOT_INIT` | 未建链 |
| 4 | `MT6835_ERR_BUS` | 总线错误 |
| 5 | `MT6835_ERR_TIMEOUT` | 传输超时：芯片不应答 |
| 6 | `MT6835_ERR_CRC` | CRC 校验失败 |
| 7 | `MT6835_ERR_NACK` | 写/烧录/置零没收到 `0x55` 应答（普通写寄存器**不**返回应答） |
| 8 | `MT6835_PROBE_PATTERN` 回读不符 → `MT6835_ERR_BUS` | 建链探针回读不匹配：芯片没在应答 |

### 排障表

| 现象 | 最可能的原因 |
|---|---|
| 建链直接失败，`err = 1` | 芯片没上电 / SPI 接线 / 片选脚不对 |
| `err = 4`（BUS）持续 | 建链探针写进去读不回来。检查 MISO/MOSI 是否接反、芯片是否上电 |
| `err = 5`（TIMEOUT）偶发 | SCK 过快或接线过长。把 SPI3 prescaler 从 4 调到 8（5.25 MHz）验证 |
| `err = 6`（CRC）偶发 | 信号完整性问题。先降速，再检查地线与走线长度 |
| `err = 6` 恒定 | SPI 模式不对（必须模式 3）或字节序不对（必须 MSB first） |
| `g_mt6835_status` 出现 `0x02` | 磁场过弱：磁钢脱落、气隙 > 3 mm、或磁钢未径向充磁 |
| 角度跳变不连续 | 磁钢偏心 > 0.2 mm，或旋转平面与芯片不平行（> 1°） |
| `g_mt6835_loops` 不增长 | 程序卡住；参考 `foc.sh debug` 读 `uwTick` 排查 |

### ⚠️ 踩过的坑：不要用 0x001 判断链路

数据手册第 10 章明确写着 0x001 是"**客户保留寄存器(EEPROM)**"，出厂未编程时为 `0x00`。
早期版本的 `mt6835_probe()` 把"读到 `0x00`/`0xFF`"当作链路故障，
结果**把一颗完好的芯片判成故障**，白白排查了半天硬件。

正确的建链判据只有两条路：
1. **写入 → 回读比对**（本驱动采用，写 0x001 这个客户保留寄存器，非破坏性）；
2. 或者看突发帧的 CRC 是否成立 —— 但这有个陷阱：总线全 `0x00` 时
   `crc8(0,0) == 0x00` 恰好等于帧里的 CRC 字节，会**假通过**，
   所以单靠 CRC 不足以证明芯片在场。

同理，**MT6835 没有器件 ID 寄存器**，任何"读 ID 校验型号"的思路在这里都不成立。

## 6. 与参考实现的差异

协议细节已逐条对照 **官方数据手册 MT6835 Rev 1.3（2022-12）** 核对，
并与 [SimpleFOC 官方 MT6835 驱动](https://raw.githubusercontent.com/simplefoc/Arduino-FOC-drivers/master/src/encoders/mt6835/MT6835.cpp) 交叉比对。
本实现有意做了几处不同：

1. **不用 union 做命令字打包**。SimpleFOC 的 `MT6835Command` 依赖结构体位域与
   字节序（该库已知在 STM32 上有可移植性问题，见其 issue #20）。
   本实现直接按字节拼数组，任何编译器/字节序都对。
2. **错误码化**，不返回 `bool`。上层能区分"超时"和"CRC 错"，排障和降级策略都更有依据。
3. **默认开 CRC**。SimpleFOC 默认 `checkcrc = false`。FOC 场景下宁可丢一帧也不能用错角度。
4. **不调 `Error_Handler()`**，初始化失败只返回错误码。

> ⚠️ 网络上流传的另一版"3 字节突发读"示例（`A0 03 00` 就取角度）与官方帧格式
> 对不上：`0xA0` 突发帧共 48 bit，角度落在第 3~5 字节；只传 3 字节拿到的是命令回显段。
> 本实现按 48 bit 处理，并已用 CRC 定义反推验证过字节位置的自洽性。
