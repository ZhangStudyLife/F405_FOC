# USART2 / JustFloat 串口

本文覆盖 USART2 串口回传与串口命令：帧布局、命令语义、驱动约束，以及 2026-09-18 起的波特率阶梯、
长测、命令接收核验和 Debug 实时路径修复记录。USB 路径见 [USB_TEST.md](USB_TEST.md)；
文本行规则、命令解析和拒绝计数由两者共用，但 UART 与 USB 各自维护半行缓冲。

## 接线与参数

PA2 → 转换器 RX，PA3 ← 转换器 TX，共地，3.3 V TTL。**2000000 baud、8N1、无流控**；
转换器为达妙 DM-USB2FDCAN 的 CDC 串口（`VID:PID=34B7:6877`，本机 COM14；不是枚举为 CH340 的 COM15）。
初始化在 `bsp_uart_init()` 中固定 2 Mbps、8 倍过采样，并把 USART2 IRQ 设为优先级 0：
2 Mbps 下每 5 µs 到一个字节，接收必须能抢占 FOC 运算。

3.5 Mbps 及 3 Mbps 已实测在发送方向可用但**命令接收不可靠**，因此不作为当前参数（见下文核验记录）。

## 回传帧（2 kHz、64 字节）

应用每 10 次 20 kHz 采样提交一帧：15 个小端 float32 + 帧尾 `00 00 80 7F`，共 64 字节。
每帧 320 µs（8N1 下 1 字节 = 5 µs），帧周期 500 µs，即占用 2 Mbps 带宽的 64%。

| 序号 | 数据 | 单位 / 含义 |
|---|---|---|
| 0 | `foc.id` | A；d 轴反馈 |
| 1 | `foc.iq` | A；q 轴反馈 |
| 2 | `adc_sample.b_voltage` | V；B 相采样电压（含运放偏置） |
| 3 | `adc_sample.c_voltage` | V；C 相采样电压 |
| 4 | 采样序号 | 24 位整数，每帧增加 10（对应 20 kHz 采样计数） |
| 5 | `foc.rpm` | 由解包机械角差计算的转速，观测用 |
| 6 | `adc_sample.bus_voltage` | V；母线电压 |
| 7 | `foc.iq_ref` | A；本周期实际使用的 q 轴参考 |
| 8 | `foc.electrical_deg` | °；电角度 |
| 9 | `foc.ud` | V；d 轴输出 |
| 10 | `foc.uq` | V；q 轴输出 |
| 11/12/13 | 已生效三相占空比 A/B/C | 0..1；本周期写入 TIM8 的值 |
| 14 | 状态字 | 转整数后：低 3 位状态、随后 4 位故障、随后 2 位功率模式 |
| 15 | `+Inf` 帧尾 | 位模式 `00 00 80 7F` |

历史协议（20 字节四字段、48 字节十一字段）只用于旧记录，工具在 [legacy/capture_foc.py](legacy/capture_foc.py)，
不适用于当前固件。

## 串口命令

文本行以 LF 结尾，也接受 CR、CRLF；应用**不发送文本应答**，通过状态与故障字段判断结果，拒绝计数见
`app_command_rejected`：

| 命令 | 行为 |
|---|---|
| `Iq 0.20` / `Iq -0.20` | 目标 Iq，单位 A；整数或最多两位小数，范围 ±5 A；越界/非有限值/非法格式被拒绝 |
| `Iq 0` | 把目标设为零；运行中仍保持电流环，待机时不启动 |
| `stop` | 立即关断功率并清参考 |
| `cal` | 仅静止待机可重新校准，成功才覆盖保存记录 |
| `clear` | 仅在故障已消失且遥测新鲜时清除到待机，不自动启动 |

`FOC_CAPTURE` 独立构建额外接受 `quiet 0/1`、`capture`、`capture low`、`capture zero`、`dump`；
`stop` 会取消采集。这些命令不存在于普通 Release。非法或超长的行被丢弃到下一个换行，不会执行其中一部分。
运行中的 UART RX 错误/丢字节会触发 `FOC_UART` 故障并关断。

## 驱动约束

- `bsp_uart_write(data, size)` 复制整帧后立即返回，最大 256 字节；双 256 字节 TX 缓冲（ping-pong），
  放不下时**整帧拒绝**并递增 `tx_rejected`，不覆盖正在发送的数据。返回 true 只代表入队，不代表已送达。
- 提交后由 `bsp_uart_tick()` 在采样/控制与 PWM 提交之后启动 DMA；不要在 SysTick 或主循环里调度正常遥测，
  SysTick 的启动相位会相对 ADC 漂移。DMA 错误只计数不自动重发（`dma_errors`）。
- `bsp_uart_read()` 从 128 字节环形队列（有效容量 127 字节）非阻塞取数据，单消费者。
- 接收是逐字节 RXNE 中断，不用 HAL 的接收路径；溢出丢字节计入 `rx_lost`，帧错误/溢出/噪声/校验错误计入 `rx_errors`。
- `g_uart_stats` 只有四个计数：`tx_rejected`、`dma_errors`、`rx_lost`、`rx_errors`。
- 不得在别处直接调用 `huart2` 的收发函数，也不要在 NMI 中调用本驱动。

## 主机测试

串口帧格式与命令解析由两个主机测试覆盖：`test_justfloat` 校验精确帧字节（毫秒时间戳 + 通道 + 帧尾）、

## 实机记录

所有记录都是电机关闭或短时空载工况：长窗口（60 s / 600 s）期间六路功率引脚保持 GPIO 低；
命令核验的驱动使能时间合计小于 16 秒。没有用示波器测过 PA2/PA3 波形。

### 2026-09-18 波特率阶梯与长测

### 2026-09-21 命令接收核验与 Debug 修复

**命令失效核验**（源码基线 `09e1b4a`，仅把 `bsp_uart.c` 改为 2 Mbps、遥测分频改为 4 即 5 kHz）：
现场读回待机时 UART RX 错误 1101、命令拒绝 1、ADC/磁编错误 0；3.5 Mbps 发 20 条 `stop` 后 RX 错误
1217（新增 116）；3 Mbps 复测 100 条 `stop` 后 RX 错误 134、命令拒绝 93；**2 Mbps 同样 100 条 `stop` 后
全部为 0，且 1 秒收到 5000 个四字段帧**。证明当时高速接收链路不可靠；未独立定位适配器波特率误差、
电气波形与中断服务各自的贡献，也不把问题归因为命令解析错误。

随后四次短时指令 +0.2 / -0.2 / +0.4 / -0.4 A 全部读到 RUN、fault=0、command 与参考等于发送值；
0.2 A 时基本静止（不能据此声称持续旋转），0.4 A 约 +1843 / -1745 RPM。所有试验的 finally 都发送 `stop`，
最终 state=IDLE、motor_mode=0、command=0、fault=0，UART 四项计数与命令拒绝全 0。运行数据 `run.bin`/`run04.bin`
为 20 字节 JustFloat 四字段（Id/Iq/B/C），SWD 用 HOTPLUG 读取、无 halt，变量跨读取并非同周期快照；
四次驱动启用总时长小于两段脚本合计 16 秒，未做耐久与模拟精度验证。电源 DPS-150 保持 20 V / 2.5 A、保护状态 0，
本轮未修改。

**VOFA 命令不启动的修复**：现场 UART 计数全 0、命令拒绝 74、FOC 状态 5 / 故障 3（TIMING），
Debug 现场 `motor_work_max=5492 cycles`（32.69 µs）、`motor_write_min=55`、`motor_timing_fault=162050`
（来源 2，谷底更新，CNT 633）——不是串口语法错误：故障锁存后运行命令被状态机拒绝，而遥测继续。
修复方式是把七个实时源文件的 `-O3` 从"仅 Release"扩展到 Debug，不改解析器、PI、保护阈值和 600 ticks 提交截止。
修复后四次短时运行（含两组独立 ±0.4 A）全部 RUN/fault 0，首组约 +1603 / -1664 RPM，
第二组每方向连续 50 条命令约 +2331 / -2340 RPM；最终 UART 四计数、拒绝、ADC/编码器错误、timing_fault 全 0，
写 CCR 最小 879 ticks（要求 ≥600）。Debug 现在保留调试信息但实时路径为 `-O3`，单步与局部变量可见性受影响。

### 2026-09-22 长窗口与 UART/USB 对比

正式 Release 同时接收 180 秒：UART 361,243 连续帧（15 float、2 kHz）零缺口；USB 侧见
[USB_TEST.md](USB_TEST.md)。同帧 CPU 对比中 UART 增量 2.50%（8×2 kHz）、2.17%（8×5 kHz）、
4.73%（1×20 kHz）、1.29%（16×2 kHz）；8 float × 20 kHz 时 UART 明确过载：拒收 243,273 帧、序号缺口 10,577。
原因是 2 Mbps 8N1 理论上限只有 200 KB/s，而 8 float × 20 kHz 至少需要 7.2 Mbps。
在线发送 36 字节需要 180 µs，由 DMA 完成，不占用 180 µs CPU；UART 8 float 的组帧 + 入队平均约 2.55 µs。

## 未验证与边界

- 逐字节 RX 中断不承诺满速持续双工；只做了短时回显和命令接收核验，没有做满速双工长测。
- 3.5 Mbps 不用于命令接收；三档 3 Mbps 复测均出现 RX 错误，未用逻辑分析仪定位原因。
- CH340 未枚举；电源串口 COM16/COM18 的探测情况见 [USB_TEST.md](USB_TEST.md) 的"未验证与能力边界"。
- 未做带载运行下的串口时延/丢帧验收，也未测 PA2/PA3 的电气波形。
