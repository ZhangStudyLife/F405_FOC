# UART / JustFloat 验证

2026-09-18，STM32F405RGT6，168 MHz，APB1 42 MHz，PA2/PA3，ST-Link V2，
达妙 DM-USB2FDCAN 的 CDC 串口 COM14。测试期间六路功率引脚保持 GPIO 低。

## 已完成的检查

- Debug / Release 编译；协议主机测试验证精确字节、数组/宏一致性、单次求值、边界和失败返回。
- 缓冲主机测试验证双缓冲所有权、过载、临时输入、非对齐输入、空缓冲不重发、
  DMA 设置时生产者抢占、启动失败/错误后恢复、RX 溢出及恢复。
- 初始速率阶梯：460800/1 kHz、921600/3 kHz、1 Mbps/3 kHz、2 Mbps/5 kHz、
  3 Mbps/10 kHz、3.5 Mbps/15 kHz，均在 5 秒发送测试中无错帧和缺帧。
- RX 64 字节突发在 1 Mbps、2 Mbps 通过；460800、921600、3 Mbps、3.5 Mbps 出现接收错误。
  尚未通过外部逻辑分析仪定位这些 RX 错误；不能宣称高波特率双向完整性。
- 4 Mbps 请求被 MCU 分频为 4.2 Mbps，端到端无法解析；4.2 Mbps 两次在 Windows
  SetCommState 阻塞并报设备错误 31，需重新插拔转换器。后续 4.667/5.25 Mbps 尝试发生在
  设备已异常期间，不能用这些失败判定其独立支持能力。

## 持续发送结果

| 波特率 | 业务帧率 | 时间 | 生成/接受/接收帧数 | 结果 |
|---|---:|---:|---:|---|
| 3.5 Mbps | 15 kHz | 60 s | 900000 / 900000 / 900000 | 零缺帧、错帧、溢出 |
| 3.5 Mbps | 17 kHz | 60 s | 1020000 / 1020000 / 1020000 | 零缺帧、错帧、溢出 |
| 3.5 Mbps | 15 kHz | 600 s | 9000000 / 9000000 / 9000000 | 1.8 亿字节，零缺帧、错帧、溢出 |
| 3.5 Mbps | 20 kHz | 5 s | 100000 / 85015 / 85015 | 14985 次提交明确拒绝，接受帧全部正确 |

15 kHz / 60 s：平均提交 133.8 cycles，最大 171 cycles（1.02 µs），
DWT 测量区间发送开销 1.59%；17 kHz 为 1.74%。
这些测量含协议封装、入队、DMA 服务及中断处理主体，不含全部异常进出栈、
函数序言/尾声和测量统计指令；不能当作精确的全系统 CPU 利用率。
ADC 周期间隔 8379～8420 cycles，主从 ADC 不完整计数为 0。
板端单独 20 kHz 的短测可无拒绝运行，测量占用约 2%，但未通过电脑端完整接收验收。
最终低频复测：1 Mbps、1 Hz，三个独立尾包均正确发送，64 字节 RX 突发也通过。

上述测试采用 3.5 Mbps / 15 kHz，保留约 14% 线路余量。当前业务为 M1 B/C 两路 ADC 引脚电压及母线电压 1 kHz 发送，ADC 同步采样仍为 20 kHz。
17 kHz 仅剩约 3% 余量；20 kHz 全量目标受当前实测链路限制，未达成。

## 调用位置与频率

当前在 `adc_test_isr()` 中每 20 对成功采样调用 `justfloat_send(adc_m1.b_voltage, adc_m1.c_voltage, adc_bus_voltage)`。硬件同步采样与结构体更新为 20 kHz，仅串口发送为 1 kHz。

协议和 UART 驱动均不限定调用频率。后续在业务定时中断或采样回调中直接调用
`justfloat_send(a, b, c)`；已有数组则调用 `justfloat_array(values, count)`。
前者直接构造完整帧并调用 `bsp_uart_write`，不经过 `justfloat_array`，节省中间复制。
需要严格等间隔时，由业务的硬件定时器决定调用周期，例如 10 kHz 每 100 µs 一次。
不要用忙等或主循环执行速度确定频率。

初始化位于 `Core/Src/main.c`，`bsp_uart_init(3500000u)` 只需执行一次。
`SysTick_Handler` 每 1 ms 调用 `bsp_uart_tick()` 聚合启动 DMA；这并不是 1 kHz 帧率限制。
USART2 中断调用 `bsp_uart_irq()`，DMA1 Stream6 中断保留 HAL DMA 处理。

# 使用方法与实现

接线：PA2 → 转换器 RX，PA3 ← 转换器 TX，共地，3.3 V TTL。
当前工程启动时配置 3,500,000 baud、8N1、无流控。

```c
#include "justfloat.h"

justfloat_send(ia, ib, voltage); // 返回 bool：true 入队成功，false 整帧拒绝
```

已有数组使用 `justfloat_array(values, count)`。支持 1～16 个业务 float；
宏参数只求值一次，不经过 double 可变参数，不要求调用者保留数组。

帧格式：`float 毫秒时间戳 | float 数据... | 00 00 80 7F`，全部小端。
时间戳来自 HAL 毫秒 tick；20 kHz 相邻帧时间戳可以相同。
float 毫秒计数在约 4.66 小时后不能逐毫秒精确表示；32 位 tick 约 49.7 天回绕。
帧尾本身是正无穷的位模式，协议没有转义或 CRC，与标准 JustFloat 一致。

驱动使用两个 1024 字节静态缓冲，SysTick 每 1 ms 尝试发送一块；
DMA 完成经 USART TC 释放缓冲，不重复发旧数据。业务提交只复制内存并立即返回。
正常带宽下聚合等待约 1 ms，另加串行传输及 USB/电脑延迟。
低速或过载时等待可能变长；缓冲满即拒绝完整消息，不覆盖正在发送的数据。

`bsp_uart_write(data, size)` 支持一次 1～1024 字节，临界区随长度增加；
本任务的 20 字节帧为优化路径。不要在 NMI 中调用，不要再直接调用 huart2 的收发函数。
`bsp_uart_read(data, size)` 非阻塞读取，单消费者；RX 环形缓冲有效容量 127 字节。
RX 是低优先级逐字节中断，不承诺高速满双工。`g_uart_stats` 提供拒绝、DMA、RX 错误计数。
返回成功仅代表入队，DMA 硬件错误会计数并丢弃受影响块，不自动重发。

当前 ADC 第一 rank 同步采集 M1 B/C 两路电压，第二 rank 采集母线电压，采样 20 kHz、发送 1 kHz，详见 `ADC_TEST.md`。2026-09-20 最终 Release 上板捕获 30,490 个连续有效帧，时间戳间隔均为 1 ms，无坏帧或发送拒绝；详见 ADC_TEST.md。
当前每帧含时间戳、三路电压及帧尾，共 20 字节；1 kHz、8N1 占用约 200 kbps。
后续调用频率由业务决定，须与实际链路带宽匹配。
