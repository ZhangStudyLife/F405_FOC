# USB CDC 与 JustFloat

本文覆盖原生 USB CDC 回传：当前 2 kHz 控制日志、VOFA+ 使用、USB 命令、队列与完整性边界，以及历史实机
短测、900 秒长测和 CPU 插桩结果。20 kHz 离线采样由独立 FOC_CAPTURE 构建写入 RAM，停机后从 UART 导出。
串口（USART2）见 [UART_TEST.md](UART_TEST.md)，两者共用命令处理但组行独立。

## 硬件与传输

PA11/PA12 使用 OTG FS，12 Mbit/s；不是 480 Mbit/s，且该 FS 控制器没有 DMA。CDC 设备在 CubeMX 初始化中
使用 RX=128、EP0 TX=64、bulk TX=128 words 的 FIFO 布局（控制端点工作时不再重新划分 FIFO）。
USB IRQ 优先级 7，低于采样/编码器 IRQ 1。

数据路径是一个 64 KB 单生产者环形队列，位于 CPU 专用 CCM（NOLOAD 数组，不占采样 DMA 使用的 SRAM）：
采样 ISR 拷贝完整帧后发布写指针，USB 完成回调（包含需要的 ZLP）之后才释放空间。一般达到 4096 字节或
距上次提交 10 ms 时开始发送，单次最多 4096 字节；持续发送时优先按 64 字节整数倍提交，空闲时尾部也会发出。
发送路径没有等待完成的循环，也不在发送路径全局关中断；CPU 仍需搬运 USB FIFO。

## 帧格式与通道

每帧 **15 个小端 float32 + 帧尾 `00 00 80 7F`，共 64 字节**，2 kHz 发送，即 128,000 B/s。
通道 0/1 是打包头字，2..14 为完整控制记录：

| 通道 | 数据 |
|---|---|
| 0 | 低 24 位 `t_u24`（TIM5 1 MHz 微秒，16.78 s 回绕）；高 8 位状态/故障/PWM 位 |
| 1 | 低 24 位 `seq`（20 kHz 采样计数，13.98 min 回绕）；高 8 位固定为 0 |
| 2..14 | `Id`、`Iq`、`Iq_ref`、`Ud`、`Uq`、母线电压、编码器机械角、电角、实测/目标转速、实际/目标位置、控制模式 |

完整通道表、位含义与单位见 [tools/bench/README.md](../tools/bench/README.md)。

时间戳是硬件计时，不是 USB 到达时间。`seq` 与 `t_u24` 都是 24 位并按 `2^24` 回绕；相邻遥测帧 `seq` 差 10、时间戳差 500 µs，可检查连续性。

## VOFA+ 设置与 USB 命令

1. 选择 Serial/串口和原生 USB 端口（本机 0483:5740，以实际枚举为准），2000000 baud、8N1、无流控。
2. 协议选择 JustFloat，开启 DTR 后连接；CDC 波特率不决定 USB 实际吞吐。
3. 若版本支持采样间隔，设 50 µs / 0.00005 s；显示刷新可设 30–60 Hz，不能靠固件降采样减轻显示负载。
4. 直接查看完整 15-float 帧；通道 0/1 是位打包头，通道 10/11 为实测/目标转速。

发送文本 `Iq 0.20` 并附加实际 CR（0x0D），也支持 LF/CRLF；HEX 等价字节 `49 71 20 30 2E 32 30 0D`。
接受整数或最多两位小数；`Iq` ±5 A、`rpm` ±9400、`pos` ±1e6°（绝对多圈角度）；
`zero` 把当前位置定义为 0°（需停机静止）；`stop` 立即关断；`cal` 仅静止待机可重校准，
`clear` 仅清除已消失的故障且不自动启动；`hello` 只在 UART 回一行文本，不进 USB 二进制流。
USB/UART 各自组行、共用命令处理，不向波形流混入文字 ACK；拒绝计数见 `app_command_rejected`。
Speed/Position 模式有 200 ms 主机看门狗（见 [App/README.md](../App/README.md)），
用 VOFA 手动发一条目标后会因不再重发而在 200 ms 后停机，这是预期行为，不是故障。

## 队列、异常与完整性边界

`g_usb_stats` 的字段顺序与 `bsp_usb.h` 声明（也是寄存器转储顺序）一致：`tx_bytes`（完成的 USB 字节）、
`tx_rejected`（满队列拒收次数）、`tx_discarded`（复位时放弃的排队字节，含未完成传输）、
`tx_high_water`（队列峰值）、`rx_bytes`、`sessions`（DTR 打开次数）、`interruptions`（关闭或挂起次数）、
`overflow`（故障锁存）。

- 仅在枚举完成且 DTR=1 时入队；DTR=0 停止入队，旧数据继续排空，重新打开是新的观察会话，可能先收到旧尾部。
  校验脚本在开始/结束时关闭 DTR 并排空 250 ms，不把跨会话间隔算成连续采集内的丢帧。
- 队列满时拒收整帧并锁存 `overflow`，停止入队，已入队数据仍可发完；USB 挂起同样锁存。
  恢复总线或仅关闭重开 COM 口不清除锁存，需复位设备或拔插重新枚举。
- 64 KB 在 720 kB/s 下只相当于约 91 ms 缓冲（正在发送的字节也占队列）。主机休眠、停读或拔线不能无限保留
  固定 20 kHz 数据；USB bulk ACK 只说明 USB 传输完成，不证明 VOFA+ 已保存全部样本。
- USB FS bulk 理想上限约 19 × 64 × 1000 = 1,216,000 B/s，实际还受主机调度、其他设备、ZLP 和中断抢占影响。
  直接写寄存器不能突破总线带宽。校准擦写、复位或采样恢复会破坏固定 20 kHz 时间连续性，不属于连续采集工况。

## 主机测试

与本篇相关的三个主机测试是 `test_usb_queue`（队列）、`test_justfloat`（帧格式）和 `test_app_usb`
（命令解析与 20 kHz 帧）；构建与运行命令见 [README.md](README.md) 的"可重复的主机测试"。

覆盖：20,000 帧逐字节比对、BUSY 重试、调用方缓冲立即复用、延迟消费、环形与 32 位计数回绕、满队列不覆盖、
溢出/挂起锁存、复位统计、RX 背压，以及精确帧字节、16 通道上限、NaN 与发送被拒、CR/LF/CRLF、拆包/粘包。
Mock 测试不验证实际中断抢占、USB 枚举和真实电机时序。

板上校验（需 pyserial，执行前关闭 VOFA+）：

```sh
python tests/capture_usb.py COM17 --seconds 60
```

脚本断言时间戳模差落在 45..55 µs、整段速率在 19,800..20,200 帧/s，并打印实测 B/s
（按 36 B/帧、20 kHz 名义为 720,000 B/s，脚本不对字节率设阈值）；帧边界丢失、时间戳非法或速率异常会抛错。
`--seconds` 最小值是 10 秒，建议 ≥30 秒以覆盖一次时间戳回绕。时间戳检查用于发现丢帧/乱序，不代替 PWM 截止测量。

## 实机验证记录（2026-09-22）

条件：STM32F405、168 MHz、20 kHz 采样、UART 2 kHz/2 Mbps、ST-Link `8600A1002031363534313541`、
原生 CDC `0483:5740`（序列号 `3862385E3335`，本轮 COM17）。**全部试验电机功率开启 0 秒**，
ADC/编码器采样与待机状态 FOC 代码持续运行——这不是带转矩运行下的控制负载测试。

**以下全部是 36 字节 / 8 通道历史布局的测量**，不代表当前的 64 字节 / 15 float / 2 kHz 布局。
当前帧率对应 128 kB/s；这些历史高负载带宽测量不代替当前固件长跑验收，见
[tools/bench/README.md](../tools/bench/README.md) 与本文末尾的未验证边界。

失败记录已保留并在端口就绪后重试。

### 900 秒长测（正式 8 通道 Release）

期间每约 5 秒通过 HOTPLUG 只读读取 USB 计数：

- 实时解析与磁盘独立复核均为 **18,000,212 个连续完整帧**，无序号缺口、乱序或帧尾错误。
- 平均 **20,000.24 帧/s、720,008 B/s**；24 位采样序号跨过一次回绕，首尾为 16,185 / 1,239,180。
- 原始文件 648,007,681 B；同步时跳过首帧，停止采集时末尾 13 B 不足一帧，不计入完整帧。
- 采集中观测队列峰值 10,540 B；结束/排空后累计峰值 24,284 B，仍低于 65,536 B。
- 最终 `tx_rejected=0`、`tx_discarded=0`、`overflow=0`；`interruptions=1` 对应正常结束时关闭 DTR。
  ADC、编码器、UART 和控制时序错误均为 0。
- 时序保持正常：采样周期与 `motor_work_max` 见 [SAMPLING_TEST.md](SAMPLING_TEST.md) 的 2026-09-22 正式 Release 行。
  这是电机关闭工况，不代表带转矩控制耗时。

证据：`endurance_900s.json`、`endurance_900s.bin`、`endurance_900s.verified.json`、`endurance_final_snapshot.json`；
原始文件 SHA-256 `b414fd4873626c7d628ea11c2e150f42629544d67568caebc1e1932805718a01`。

长测后运行中整段 Flash 读回出现少量差异，降低 SWD 时钟后仍存在；随后确认门极关闭、暂停 CPU 再读，
整个固件逐字节一致，24 B 校准区与初始备份一致。这支持差异来自运行中调试读回过程，未定位底层原因，
不报告为固件损坏。读回后复位回安全待机，COM17 重新枚举正常，`final_idle_snapshot.json` 确认状态/故障为 0、
功率通道禁用、门极 GPIO 低。

### CPU 与实时性（插桩）

使用 TIM2 84 MHz 计时（包含 WFI 时段），基线保持相同 20 kHz 采样、UART 2 kHz 和电机关闭，只关闭 USB 回传：

| 工况 | 整机忙碌 | USB IRQ 独占 | USB IRQ/s |
|---|---:|---:|---:|
| USB 未回传（电机关闭基线） | 37.21% | 0% | 0 |
| 8 通道，1 KB 批量 | 46.75% | 3.354% | 4,268 |
| 8 通道，4 KB 批量 | 46.28% | 3.010% | 3,867 |
| 8 通道，双向传输 | 46.85% | 3.400% | 4,838 |

4 KB 批量相对 1 KB 使 USB IRQ CPU 开销下降约 10.2%、中断数下降约 9.4%；含组帧/拷贝/调度的整机增量约
9.08 个百分点，因此不能把 3.01% 当作 USB 全链路成本。8 通道插桩中 USB ISR 最大墙钟约 27.05 µs
（可能包含高优先级采样抢占），控制时序故障计数 0；采样侧数字见 [SAMPLING_TEST.md](SAMPLING_TEST.md)。
数据包含插桩与异常入口/退出开销，不能当成无插桩 Release 的精确占用。

CPU 插桩构建（`USB_PROFILE`）**不在版本库中**：选项与 `usb_profile.c/.h` 只存在于本地
`build/commit_review/` 与 `build/USB-Profile/`，普通 Release 不含插桩和压力测试 RX sink。

### 与 UART 的同帧对比

同一测试固件依次只开 UART / USB，用完全相同的 float 数组与 +Inf 帧尾直接调用各 BSP（不调用会额外加入
时间戳的 `uart_justfloat`），CPU 为 TIM2 插桩整机忙碌率减去基线 34.7882%：

| float 数×频率 | UART 增量 CPU | USB 增量 CPU | 连续性 |
|---|---:|---:|---|
| 8×2 kHz，72 KB/s | 2.50% | 4.83% | 两路通过 |
| 8×5 kHz，180 KB/s | 2.17% | 5.75% | 两路通过 |
| 8×20 kHz，720 KB/s | 过载，拒收 243,273 帧 | 10.51% | 仅 USB 通过 |
| 1×20 kHz，160 KB/s | 4.73% | 8.36% | 两路通过 |
| 16×2 kHz，136 KB/s | 1.29% | 5.10% | 两路通过 |

结论：当前驱动下低带宽 UART DMA 更省 CPU，8 float×20 kHz 必须使用 USB。最终恢复迁移路径后的正式 Release
同时接收 180 秒：USB 3,599,814 连续帧、UART 361,243 连续帧（原有 15 float、2 kHz），均零缺口，
USB 磁盘独立校验通过；队列峰值 11,296 B，USB 拒收/丢弃/溢出与 UART/ADC/编码器/控制时序错误均零。

## 未验证与能力边界

### 2026-09-23 历史 52 字节布局复测

该历史版本 12 float + 帧尾布局曾在电机功率关闭时连续采集 180 秒：3,600,226 帧，187,211,776 原始字节；相邻 `seq` 均差 1、时间戳均差 50 µs、故障帧 0。USB 队列读回 `tx_rejected=0`、`tx_discarded=0`、`overflow=0`，峰值 19,636/65,536 字节，ADC/电机时序故障 0。名义速率为 **1,040,000 B/s**，不能写成 960 kB/s。原始文件与计数快照见 `build/bench_debug/20260923_0942_review/`。

这是电机关闭的 180 秒带宽验收。接线修好并把 1 kHz 外环计算移到 PWM 提交后，12 V、720° 工况在四个日志组各运行 5 秒，分别记录 109,961/109,961/109,961/109,882 帧，均无丢帧、故障或 USB 队列溢出；24 V 的速度、位置和正反力矩短测也通过。最终固件读回 `motor_write_min=693`，仍只有 93 ticks 的提交余量。带电机运行的 180 秒耐久尚未覆盖，不能用电机关闭的长跑代替。

- 未做带转矩运行下的控制负载、满负载、Windows 系统睡眠/唤醒、USB 电气信号测量或 VOFA+ 长期绘图验收。
- 64 KB 在 720 kB/s 下只提供约 91 ms 队列容量；主机停读 500 ms 的反例已实测，不能承诺无限保留数据。
- 增加通道数必须重新长期验证，不能根据 12 Mbit/s 标称值承诺吞吐。
- 本轮电源串口 COM16 查询超时、COM18 无有效身份回复，未更改任一电源输出或设置；CH340 未枚举。
  停机状态通过 SWD 只读确认 TIM8 功率通道禁用且三相门极 GPIO 输出低。
